# Teams

A team is onboarded with one pull request, generated by
`python3 ci/new-team.py <name> [--gpu N]`, that adds three things:

- `argocd/apps/team-<name>.yaml`: the team's Argo CD project (only VllmService and
  FleetService, only in namespace `team-<name>`, nothing cluster-wide) and two
  applications, one for the platform-owned tenant and one for the team's services.
- `tenants/<name>/`: owned by the platform: the namespace; a quota on GPUs, CPU,
  memory and pods; a LimitRange with CPU and memory defaults; and a default-deny
  ingress NetworkPolicy, enforced by Dataplane V2.
- `teams/<name>/`: the team's own manifests.

`ci/check-tenancy.py` fails the build if a team project can manage anything outside its
namespace, if a manifest targets another namespace, if a tenant has no GPU quota,
no LimitRange with CPU and memory defaults, or no default-deny ingress NetworkPolicy.

Not yet: enforced Pod Security, identity per team, and per-client identity and rate
limits at the edge. None of this has been applied to a live cluster yet.
